EXTRACTION RULES:

Motions:
- Extract every motion put to a vote by a councillor, including procedural ones (confirmation of minutes, receiving reports, suspending/resuming standing orders, etc.)
- Do NOT extract the presiding member's declaration of opening or closure of the meeting — these are administrative declarations, not council motions
- Do NOT extract officer/administration recommendations as motion records — only extract the actual motion moved by a councillor
- `item_number`: use the agenda item number exactly as printed (e.g. "7", "11.1.1"); null if not shown
- `title`: short label, 5–10 words
- `motion_text`: verbatim resolution text exactly as written in the document
- `description`: contextual background about the item only — NOT the resolution text itself
- `outcome`: map the result word to the enum — "CARRIED" → "carried", "LOST" → "lost", etc.; null only if no outcome is stated and cannot be reasonably inferred
- If a motion was LOST and a foreshadowed/amended motion was then put to the vote, record both as separate motion objects
- For the foreshadowed/amended motion: if the text shows it was put to the vote but the outcome word is missing (e.g. the page is cut off), set outcome to "carried" — a motion that is put and not recorded as lost is assumed carried
- Only create a motion record when there is an actual resolution/motion text or a clear vote outcome in the minutes — do not create records for agenda items that are merely reports or information items with no associated motion

Votes:
- `individual_votes`: list each councillor separately with their "for"/"against"/"abstain" choice — extract from lines like "For: Cr Smith, Cr Jones / Against: Cr Brown"
- `votes_for` / `votes_against`: use the aggregate count from text like "CARRIED (8/1)" — 8 for, 1 against; omit if individual votes already capture the detail
- Councillors who declared an interest and left the chamber should have `declared_interest: true` and their `choice` set to "absent"

Planning applications:
- If a motion relates to a development/planning application (DV, DA, planning scheme amendment, etc.), always populate the `planning_application` object
- `reference_number`: the DV/DA/application number (e.g. "DV23.42")
- `status`: set to "approved" if CARRIED, "refused" if LOST, "deferred" if outcome is deferral
- Extract community submissions (objections/supports) count and any named submitters

Councillors:
- `councillors_present`: list only elected members — Mayor, Deputy Mayor, and Councillors; exclude officers, CEO, directors, and staff
- `councillors_apology`: elected members who gave apologies

General:
- Use ISO 8601 date format (YYYY-MM-DD) for all dates
- Infer tags from context: e.g. "planning", "budget", "infrastructure", "community", "governance", "procedural"
- If a value is not present in the text, use null or empty list as appropriate

Other items:

- `item_type`: a short label describing the category (e.g. "petition", "budget", "policy amendment", "officer report", "correspondence")
- `description`: one or two sentences summarising the content and any decision or action taken
- Do NOT silently discard substantive content — if it doesn't fit elsewhere, it belongs in `other_items`
- Routine procedural items with no substantive content (e.g. opening, closure, declarations of quorum) do not need to be recorded here
